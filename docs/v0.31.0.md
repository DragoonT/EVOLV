# EVOLV v0.31.0 — durable engineering

This release is backend-heavy: the agent, runtime and storage layers were
rebuilt so long assignments survive interruption, verify themselves, and stay
observable. The UI changed only where a new backend capability needed a face.

## Major improvements

### Durable execution state (`internal/execution`)
- Tasks carry a real lifecycle: `queued → planning → running → waiting →
  verifying → paused → completed / failed / cancelled`, with an explicit
  transition table. Illegal moves are rejected, not silently applied.
- Dependency graph: cycle detection, dangling-dependency reporting, priority
  ordering, blocked-task discovery and per-file conflict detection.
- Append-only journal (`journal.ndjson`) with sequence numbers, plus an
  atomic snapshot (`run.json`). A torn final record is truncated, never
  folded into state.
- Crash recovery: any task that was mid-flight when the process stopped is
  put back to `queued`, its attempts are preserved, and the reason is
  recorded — it is never presented as still running.

### Agent protocol hardening
- Fence detection is string-aware: a ` ``` ` inside generated code no longer
  ends the block.
- A balanced scanner extracts actions, rejects malformed JSON, caps size,
  nesting and action count, and reports every problem back to the model as
  `protocol_error` so it can repair itself.
- Fenced blocks take precedence; unfenced prose examples are only salvaged
  when a turn contains no fenced block at all.

### Loop protection
- Budgets: turns, wall clock, identical batches, consecutive failing
  batches and total tool output per turn.
- Cancellation is reported to the user and recorded.
- Every stop prints why it stopped.

### Provider reliability
- SSE and Anthropic streams are decoded with a byte reader: split frames,
  CRLF, comments, multi-line data, missing `[DONE]` and malformed events all
  work or are skipped, never fatal.
- Errors are classified (`auth`, `rate_limit`, `quota`, `server`, `network`,
  `timeout`, `cancelled`) with `Retry-After` support and user-facing hints.
- `StreamWithRetry` retries transient failures with exponential backoff and
  jitter; it never replays a stream that already emitted content.
- Credentials are redacted from every error path.

## Runtime and filesystem
- Plugins: listener, timer, bridge-call and event-fire budgets enforced at
  the bridge; `evolv.off`; limits surface as `plugin:warning`; reload stops
  the previous runtime.
- `workspace.AtomicWrite`, `GuardedWrite` (sha256 contracts) and
  `CheckWithin` (symlink-escape detection) are shared by the agent and the
  Workbench.
- Workbench writes are atomic and conflict-aware: `409` with `current_hash`
  when the file changed since it was read; reads return the hash.

## Self-evolution
- `candidate.PromoteBinary` performs a transactional swap: backup, staged
  rename, restore on failure, windows fallback, and explicit reporting.

## Workspace
- Versioned migrations with a journal (`workspace/migrations.json`).
- `evolv migrate [--dry-run] [--json]` inspects or applies upgrades without
  starting the server.
- Corrupt `plan.json` is quarantined, never deleted.

## Observability
- Per-turn and per-tool counters, last-turn duration, per-action tool counts
  (bounded label cardinality) in Prometheus `/api/metrics` and in
  `/api/health` under `runs`.
- `/api/runs`, `/api/runs/detail`, `/api/runs/events`, `/api/runs/create`,
  `/api/runs/transition` expose durable work to clients.
- A quiet Runs panel in the sidebar reflects real run state.

## Migration notes
- The workspace schema upgrades itself on first boot of v0.31.0. Nothing is
  deleted; unreadable plan files are preserved with a `.corrupt-<timestamp>`
  suffix.
- Existing tool manifests, plugin manifests, conversations, snapshots,
  ledgers and DNA assets are untouched.
- No action names or config keys changed.

## Limits and honest caveats
- Plugin memory is not hard-capped: goja cannot enforce a heap limit. Time,
  call-stack, listener, timer and bridge budgets are enforced; memory remains
  a process-level concern.
- The execution store is journal + snapshot on disk, not a database. That is
  deliberate: single binary, no external services.
- Windows binary replacement of a *running* executable uses the park-and-copy
  fallback and reports it explicitly.
